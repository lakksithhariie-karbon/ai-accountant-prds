Bill Splitter

AIA automatically identifies when an uploaded PDF contains multiple bills, asks the user to confirm the proposed split inside the existing upload flow, and then sends each resulting bill through the normal extraction, review, approval, and Tally journey.

The Problem#

Suppliers often send several invoices together in one PDF, especially at month-end. AIA is built to process one bill at a time and deliberately limits a single bill to 12 pages so extraction remains accurate and reliable. Today, when a multi-invoice PDF is uploaded as one bill, it can either fail because it exceeds the page limit or be interpreted as one voucher, mixing details from different invoices.

This affects CAs and accountants who upload vendor bills into AIA and sync approved vouchers to Tally. The user has no in-flow way to fix the file, so they either leave AIA to split the PDF manually or discover the mistake later during review or accounting.

  • Repeated manual PDF splitting outside AIA.
  • Failed uploads with no recovery path inside the workflow.
  • Mixed-up vouchers that create review and ledger clean-up work.
  • Lower trust in AIA during high-volume month-end processing.

Job Stories#

The user is a CA or accountant uploading vendor bills through AIA. They want AIA to handle multi-invoice PDFs without making them leave the product or manually prepare the file first.

When there’s a particular situation I want to perform an action or find something out So I can achieve my goal
I upload one PDF that contains several separate invoices. I want AIA to identify the individual bills and show me where it plans to split them. I can confirm the result without leaving AIA or using another PDF tool.
AIA is unsure where one bill ends and the next one begins. I want the uncertain boundary clearly highlighted and editable. I can correct the split before the bills continue into review and accounting.
I have reviewed the proposed split and everything looks correct. I want to confirm once and have AIA create the individual bill files. Each bill can be extracted, reviewed, approved, and synced independently.

Scope#

This work adds bill splitting to the existing AIA upload journey. It does not create a new product or replace AIA's extraction and review experience.

In scope
  • Detect when an uploaded PDF should be split.
  • Find proposed bill boundaries page by page.
  • Open a split-review modal inside AIA.
  • Let users confirm, add, remove, or correct boundaries.
  • Let users exclude irrelevant or blank pages.
  • Flag uncertain boundaries that need review.
  • Create the confirmed bill files within AIA's page limit.
  • Return each bill to the normal AIA flow.
Out of scope
  • No change to Upload Bills or accepted file types.
  • No separate splitter app, login, navigation, or history.
  • No replacement of AIA's field extraction.
  • No separate approval experience inside the split review.
  • No automatic continuation when a required boundary is unresolved.

User Flow#

The user enters through the same Upload Bills experience they use today. AIA checks the uploaded PDF and only introduces split review when the file should not continue as one bill. The user reviews the proposed boundaries, resolves anything uncertain, confirms, and returns to the standard AIA workflow.

Important edge cases remain inside this journey: a safe single bill bypasses split review; uncertain boundaries block confirmation until resolved; confidently blank separator pages may be excluded automatically but remain restorable; a failed analysis shows a readable retry state; cancelling leaves the upload uncommitted.

Solution#

We will embed the proven bill-splitting capability into AIA as a modal step that appears only when the uploaded PDF should not continue as one bill. AIA proposes the boundaries, the user reviews only the places that need judgment, and confirmation creates the individual bill files without taking the user out of the existing AIA experience.

The split review should answer one question: “Are these the correct bills?” The system should combine reliable document signals with AI judgment, keep continuation pages and annexures with the correct bill, and make every uncertain boundary explicit rather than silently guessing.

  • Detect: identify separate bills using invoice numbers, supplier identity, page continuity, layout changes, and AI judgment.
  • Review: show page previews and proposed boundaries; allow add, remove, confirm, correct, exclude, and restore actions.
  • Validate: every page must belong to a bill or be explicitly excluded; unresolved boundaries block confirmation.
  • Create: produce individual bill files that respect AIA's downstream page limit. A single unusually long bill is divided into sequential parts that stay associated with the same bill.
  • Continue: return each resulting bill to the normal AIA extraction → Needs Review → approve → Tally flow. The splitter never auto-approves a bill.

Acceptance Criteria#

  • The existing Upload Bills entry point remains unchanged.
  • A safe single bill continues normally without showing split review.
  • When splitting is required, the modal shows every page and the proposed bill boundaries.
  • The user can add, remove, confirm, or correct a boundary and can exclude or restore a page.
  • Any boundary marked as uncertain remains visibly unresolved until the user confirms or corrects it.
  • Confirm is unavailable while any page is unassigned or any required boundary remains unresolved.
  • Blank separator pages may be auto-excluded only when confidently blank and must remain visible and restorable.
  • No resulting file exceeds AIA's downstream page limit; a longer single bill is split into ordered parts associated with the same bill.
  • Cancelling the modal creates no split bills and does not silently continue with an unreviewed split.
  • If split detection fails, the modal shows a readable error and a retry action.
  • After confirmation, each resulting bill enters AIA as an independent item and follows the normal extraction, Needs Review, approval, and Tally flow.
  • The splitter never auto-approves or bypasses AIA's existing review step.
