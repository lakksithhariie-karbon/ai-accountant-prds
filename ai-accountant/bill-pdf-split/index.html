Product Requirements Document

Bill Splitter

At month-end, suppliers often send several invoices in one PDF, forcing accountants to split files manually or risk mixed bill data. Bill Splitter detects when a packet contains more than one bill, proposes the page-by-page grouping, and brings any uncertainty into a focused review step. The accountant confirms or corrects the split once, then each bill continues independently through the existing extraction, review, approval, and Tally workflow.

The Problem#

At month-end, suppliers often send several invoices together in one PDF. AIA’s existing bill extraction module is designed to process one bill at a time and currently supports up to 12 pages per bill. When a user uploads a file above that limit, extraction fails.

This limit exists for a good reason. The existing extraction module is designed to read one bill at a time. When several bills are sent together in one file, there is too much information to extract reliably in one pass. This makes the extraction task harder and increases the risk of inaccurate or hallucinated bill details.

As a result, accountants have to manually prepare the supplier’s document before it can be processed. They split the PDF into smaller bill files outside AIA, then upload the parts individually. This adds manual work at the busiest point of the month and creates avoidable risk: a page can be missed, a bill can be duplicated, or the wrong pages can be grouped together.

  • Files above the 12-page per-bill extraction limit fail.
  • Accountants manually split supplier PDFs into smaller bill files before processing.
  • Multi-bill PDFs cannot be safely passed through the existing one-bill extraction workflow.
  • Manual splitting creates extra work and can lead to missed, duplicated, or wrongly grouped pages.
  • Large, scanned, and repetitive month-end packets add friction to the upload journey.

Solution#

Bill Splitter keeps the supplier’s original PDF inside AIA and turns it into a reviewable proposed split. It separates the work into two clear places: Bill Uploads is where a file is uploaded, read, and made ready for review; Needs Review is where individual, extracted bills are checked as part of the existing accounting process.

The split review answers one question: “Are these the correct bills?” It is not an approval screen and it is not an extraction editor. The system proposes the grouping; the accountant confirms the result before individual bill files exist.

  • Detect: identify likely bill starts from invoice details, supplier identity, page continuity, layout changes, and document understanding.
  • Prepare: show In progress while the file is read, then show Split ready when the proposed split can be reviewed.
  • Review: show pages as the editing surface and let the user add a missing split, remove a wrong split, exclude a page, or restore a page directly on the relevant page.
  • Validate: every page must belong to a bill or be explicitly left out; unresolved required boundaries block confirmation.
  • Create: produce separate bill files that respect the 12-page downstream limit. A genuinely longer invoice becomes ordered, linked parts rather than unrelated bills.
  • Continue: extract each confirmed bill and send it to AIA Needs Review. Bill Splitter never auto-approves or directly posts to Tally.

Scope#

Bill Splitter adds a guided multi-bill PDF path to the existing Purchases upload journey. It starts when a supplier packet is uploaded and ends when the accountant confirms the proposed bill grouping. After that point, each resulting bill returns to AIA’s existing extraction, Needs Review, approval, and Tally workflow.

In scope
  • Entry through Purchases → Upload Bills and the existing upload modal.
  • Accept one supplier PDF that may contain one bill or several bills.
  • Show the uploaded file in Bill Uploads while it is being read and prepared.
  • Show clear file states: In progress, Split ready, Failed, and Completed.
  • Identify and propose where each bill starts, including continuation pages and likely blank separator pages.
  • Read smaller packets as one file and process larger packets in page groups before combining the result.
  • Open Review split only when a multi-bill packet needs the accountant’s decision.
  • Show every page, each proposed bill grouping, excluded pages, and unresolved boundaries.
  • Let the accountant add a missing split, remove a wrong split, exclude a page, or restore a page.
  • Prevent confirmation until all pages are accounted for and required boundary decisions are resolved.
  • Create separate bill files within the 12-page downstream extraction limit.
  • Send each confirmed bill into the existing extraction → Needs Review → approval → Tally flow.
Out of scope
  • No replacement of the existing bill extraction module.
  • No change to the existing Needs Review screen, approval controls, or Tally sync workflow.
  • No automatic approval, posting, or direct voucher creation by Bill Splitter.
  • No separate Bill Splitter app, navigation item, login, or standalone document library.
  • No promise that every packet can be split without accountant review.
  • No automatic confirmation when a bill boundary is uncertain or page coverage is incomplete.
  • No silent deletion of pages identified as blank or irrelevant.
  • No support for packets above the configured 100-page upload limit in this phase.
  • No change to accepted upload file types in this phase.

User Flow#

The user starts from AIA’s left navigation and clicks Purchases. Inside Purchases, the user selects Upload Bills and uploads the supplier’s original PDF through the existing upload modal. The uploaded file then appears under the Bill Uploads tab while AIA reads the pages and prepares the next action.

Flow 01 · Purchases, upload, and routing
01

Purchases menu

User clicks Purchases from the left navigation.

02

Upload Bills

User selects Upload Bills from the Purchases screen; the existing upload modal opens.

03

Upload PDF

User selects the supplier PDF and completes the normal upload action.

04

Bill Uploads

The file appears under the Bill Uploads tab with In progress while AIA reads and prepares it.

05

Route the file

A safe single bill continues to extraction. A packet that needs splitting changes to Split ready and exposes Review split.

The existing 12-page extraction limit must not be shown as an upload failure when the PDF is eligible for Bill Splitter. A PDF that can be handled by Bill Splitter stays in the normal upload journey, appears in Bill Uploads, and is prepared for split review instead of being rejected because it contains more than 12 pages.

Flow 02 · What happens after Split ready
01

Split ready

The Bill Uploads row shows Split ready with a Review split action.

02

Review split

User opens the review surface and sees every page grouped into the bills AIA proposes to create.

03

Resolve issues

User adds or removes splits, excludes or restores pages, and resolves any required uncertain boundary.

04

Confirm split

Once every page is accounted for and required decisions are resolved, Confirm split becomes available.

05

Continue in AIA

AIA creates the individual bill files, extracts each one independently, then sends them to existing Needs Review, approval, and Tally flow.

A page identified as blank or irrelevant remains visible in Review split with a one-click Put back action. A proposed cut is labelled as suggested; a cut added by the accountant is labelled as added; and a suggested cut the accountant removes remains visibly marked as removed. Cancel closes the review without creating bill files.

Failure handling. If the PDF cannot be read or analysed, the failure stays on the same Bill Uploads row with a plain-language reason and Retry only when retrying can help. Files above the configured 100-page limit stop with a clear page-limit message rather than entering split review.

Acceptance Criteria#

  • The user enters the flow by clicking Purchases from AIA’s left navigation, then selecting Upload Bills on the Purchases screen.
  • A PDF that is eligible for Bill Splitter must not fail only because it exceeds the existing 12-page downstream extraction limit; it is routed through Bill Uploads and prepared for splitting instead.
  • When a split is ready, the Bill Uploads row shows Split ready and exposes Review split.
  • After the user confirms the split, AIA creates the resulting bill files and continues each bill independently through extraction → Needs Review → manual approval → existing Tally flow.
  • A multi-bill PDF first appears in Bill Uploads, not Needs Review.
  • A safe single bill continues through normal extraction without showing split review.
  • Files above 100 pages stop with a readable explanation and a useful next step.
  • The modal shows every page, proposed bill boundaries, excluded pages, and unresolved boundaries.
  • The user can add a missing split, remove a wrong split, exclude a page, or restore a page.
  • Automatically proposed blank pages remain visible and restorable; no page is silently discarded.
  • Every source page is represented exactly once as a bill page or an explicitly excluded page; gaps and overlapping assignments block confirmation.
  • Confirm is unavailable while any required boundary is unresolved.
  • No resulting file exceeds AIA’s 12-page downstream extraction limit; a longer single bill is created as ordered, associated parts.
  • Cancel creates no split bills and does not continue with an unreviewed result.
  • Analysis failures are shown in Bill Uploads with plain-language guidance; Retry appears only when it can help.
  • Bill Splitter never auto-approves a bill, bypasses Needs Review, or posts directly to Tally.
